# ดัชนี Flow สำหรับ UI มือถือของ Squid first

ใช้ตัวอักษร **A–H** จาก Mobile Developer Handoff ใน Stitch แล้วเติมเลขหน้าและสถานะ ตัวอย่าง `A01` คือหน้าภาพรวม ส่วน `A01.05` คือภาพรวมในสถานะ Zero Queue ตัวอักษรท้าย เช่น `a` และ `b` ใช้กับภาพหลายแบบของสถานะเดียวกัน ใช้รหัสนี้ในชื่อเฟรม งาน dev และชื่อภาพทดสอบเพื่อค้นย้อนกลับได้

อ้างอิง **Mobile Developer Handoff & Implementation Spec** `b32d4a471da648cf96d582a281ec04a9` และ **Mobile User Flow & Navigation Map** `10c771bf6f35408abd0dfbe53ea5f61a` [โปรเจกต์ Google Stitch](https://stitch.google.com/projects/9946906478898127464)

Canvas มีป้าย «หน้าหลัก 01 · ภาพรวม» ซึ่งระบุ `sourceScreen` เป็นคลังประวัติแชท `6b3907e44ecb422192c1ef04858ce3d0` ส่วนการเปิดเฟรม `286614…` โดยตรงแสดงแบบ A ตาม A01.01a เก็บการอ้างอิงสองรายการนี้ไว้เพื่อยืนยันเฟรมฐาน เฟรม `d5331699295f43b497b546a572dab403` ถูกตัดออกตามที่เจ้าของโปรเจกต์แจ้ง

ตรวจป้ายบน Canvas แล้วพบรหัส A01 ครบ 9 ป้าย ส่วน A01.01a, A01.01b และ A01.08c ใช้รหัสจากดัชนีนี้จนกว่าจะยืนยันการจับคู่กับป้ายบน Canvas ได้

สำหรับการพัฒนาให้จับคู่ **รหัส Flow + เส้นทางแอป + รหัสเฟรม + เงื่อนไขข้อมูล** แต่ละรหัสใน A01 ใช้หน้าภาพรวมเส้นทางเดียวกัน การเปลี่ยนสถานะจะอ้าง API ตามข้อมูลของสถานะนั้น [ตารางหน้าจอและ API](screen-route-matrix.md)
