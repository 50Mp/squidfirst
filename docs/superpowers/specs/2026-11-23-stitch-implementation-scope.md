# Squid first — ขอบเขตการนำ UX/UI ไปพัฒนา

วันที่: 23 พฤศจิกายน 2026 · โค้ดตั้งต้น: `d65fc6f`

## เป้าหมาย

นำแบบ Game Top-Up Operations Hub ใน Stitch มาเป็นแอดมินใช้งานจริงบน Telegram Mini App และ Web ให้หน้าตาและลำดับงานต่อเนื่องกัน ใช้ข้อมูลจริงจากระบบเดียวกัน เริ่มที่เจ้าของร้านหนึ่งคนและการเติมเกมด้วยมือ

## สถานะที่ตรวจแล้ว

- มี React/Vite admin, Fastify API, ฐานข้อมูลและ Telegram integration อยู่แล้ว
- มีภาพรวม ออเดอร์ แชท/ลูกค้า จัดการร้าน สินค้า/โซน/กำไร แหล่งข้อมูล เรท การตั้งค่า audit และ backup
- มีธีม #2563EB, mobile bottom navigation, desktop list/detail, return context, primary next action, global badge และ issue context ในแชท
- แก้ initial/cached FX read failure และ customer-history false-empty แล้ว
- ผลทดสอบที่บันทึกไว้: backend 51 กรณี และ browser 26 กรณี ไม่ได้รันเทสต์ใหม่ในการวางแผนครั้งนี้
- โค้ดปัจจุบันเป็นการปรับแบบเข้ากับความสามารถของ API เดิม ยังไม่ใช่หลักฐานว่าทุกหน้าใน Stitch ถูกนำมาทำครบ หรือหน้าตาตรงทุกองค์ประกอบ
- ยังไม่มีหลักฐานทดสอบรุ่นล่าสุดบน Telegram ในโทรศัพท์จริง และยังไม่ได้เปิดใช้รุ่นใหม่ด้วยการ restart production

## ข้อกำหนดร่วม

- สีหลัก #2563EB พื้นขาว ตัวอักษรไทยอ่านง่าย; พัฒนาทั้ง Mobile และ Web จากแบบที่เลือก
- หนึ่งบัญชีลูกค้ามีหนึ่งห้อง รวมบทสนทนาและบริบทออเดอร์ของคนนั้น
- การเปลี่ยนสถานะเป็นข้อมูลระบบ ไม่ใช่ข้อความสนทนาที่ส่งให้ลูกค้าโดยอัตโนมัติ
- ราคาแสดงขายเป็น USD; ต้นทุน/เรทเดิมบันทึกใน snapshot ห้ามคำนวณออเดอร์เก่าทับด้วยเรทใหม่
- การดึงร้านและ LFX ต้องอยู่ในช่วง 15:00 <= เวลา < 16:00 UTC+7; refresh หน้าจอเป็นการอ่านข้อมูลที่เก็บแล้ว
- 10% คือ markup บวกจากต้นทุนตามโค้ดปัจจุบัน ไม่เปลี่ยนเป็น gross margin โดยเงียบ ๆ
- ร้านต้นทางสองร้านคือ JorJee และ GGXG; เปิด–ปิดแยกได้; จับคู่เฉพาะเกม/โซน/แพ็กเกจที่ตรวจว่าเทียบกันได้
- ไม่สร้างตัวเลข latency, กำไรสุทธิ, VIP, auto-fulfillment หรือเกมที่ยังไม่รองรับให้ดูเหมือนเปิดใช้งานแล้ว
- คง owner authentication, CSRF/Origin, revisions, idempotency, audit และแยก MOCK จากยอดจริง

## ขอบเขตรุ่นแรก

หน้าหลักทั้งสี่และหน้ารองสำหรับปฏิบัติงานต้องตรงแบบอ้างอิงที่ล็อกไว้ มี loading/empty/error/retry/disabled/success ครบ ใช้ข้อมูลจริง พร้อมทดสอบผ่าน Telegram บนอุปกรณ์จริงและเปิดทดลองแบบควบคุมได้

## ชุดงานถัดไปที่ต้องออกแบบสัญญาข้อมูลก่อนลงโค้ด

- ขอคืนเงิน → รอคืนเงิน → บันทึกหลักฐาน → คืนเงินแล้ว ทั้ง Web/Telegram; ยังไม่ใช่การโอนเงินอัตโนมัติ
- เปิด/ปิดเคสและคลังแชทต้องแยกจากสถานะออเดอร์; PDF/export ต้องมีขอบเขตข้อมูลและสิทธิ์ดาวน์โหลด
- รายงานกำไรสุทธิ/ledger ต้องมีข้อมูลค่าธรรมเนียม โปรโมชั่น คืนเงิน และนิยามช่วงเวลา; ไม่เปลี่ยนชื่อรายงาน gross-profit เดิมเป็น net profit
- โปรโมชั่นและหลายแอดมินต้องมีข้อกำหนดเรื่องส่วนลด สิทธิ์ ผู้รับงาน และการชนกันของการแก้ไข
- PUBG/Roblox, ตรวจ UID กับผู้ให้บริการ, auto top-up/failover/circuit breaker ต้องมีแหล่งข้อมูล/สัญญา API ที่ตรวจสอบแล้ว แยกจากรุ่น manual ปัจจุบัน

## ทางเลือกการพัฒนา

เลือกต่อยอดระบบเดิมและทยอยส่งมอบตาม flow เพราะมี backend และเทสต์รองรับแล้ว การสร้าง frontend ใหม่ทั้งชุดจะเพิ่มงานเชื่อม auth/state และเสี่ยงทำพฤติกรรมเดิมหาย ส่วนการคัดลอก HTML ทุกหน้าจาก Stitch จะนำข้อมูลตัวอย่างและปุ่มที่ยังไม่มีระบบรองรับติดมาด้วย
