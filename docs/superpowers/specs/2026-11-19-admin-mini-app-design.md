# Squid first Admin Mini App — แบบและขอบเขต

สถานะ: สรุปจากบทสนทนาเพื่อทบทวนก่อนเริ่มเขียนโค้ด งานรอบนี้แก้เอกสารเท่านั้น

## เป้าหมาย

เจ้าของร้านทำงานได้ครบทั้งใน Telegram Mini App และปุ่ม/ห้องแชทของบอต โดยข้อมูลออเดอร์ การชำระเงิน และบทสนทนาเป็นชุดเดียวกัน เริ่มแอดมินหนึ่งคน เตรียมสิทธิ์ ผู้รับผิดชอบงาน และประวัติการแก้ไขสำหรับทีมในอนาคต

## สิ่งที่มีแล้ว และส่วนที่ยังขาด

- มี Fastify/TypeScript, PostgreSQL, ข้อมูล Mobile Legends และ Free Fire, ร้าน JorJee และ GGXG และตัวดึงเรท LFX
- มีบัญชีลูกค้า ห้องแชทประจำบัญชี ออเดอร์ สลิป การเปลี่ยนสถานะ และ Telegram outbox
- บอตมีหนึ่งห้องต่อบัญชี รวมออเดอร์และแชท ไอคอนตามงานค้าง ปุ่มตามสถานะ และการ์ดออเดอร์เดิมที่อัปเดตได้
- ยังไม่มีหน้า Admin Mini App, การยืนยันตัวแอดมินผ่าน Mini App, source toggles แบบถาวร และ FX mode ที่เลือกใช้ manual โดยไม่ถูกข้อมูล LFX ใหม่ทับ
- ยังไม่มีหน้าร้านลูกค้าจริง และการเปิดรับออเดอร์จริงยังต้องผ่านการตรวจพร้อมใช้งานแยกต่างหาก
- PUBG Mobile และ Roblox เป็นเกมที่ขอเพิ่ม ยังไม่ใช่เกมที่มีข้อมูลพร้อมขายในระบบ การเพิ่มแหล่งข้อมูล/วิธีเติมของสองเกมนี้เป็นงานตามหลัง ไม่ปลอมแพ็กเกจหรือโซนเพื่อเติมช่องว่าง

## โครงหน้าจอ

แถบล่างสี่เมนู: **ภาพรวม / ออเดอร์ / แชท / จัดการร้าน**

1. ภาพรวม: ยอดขาย/กำไรขั้นต้นที่คำนวณได้ งานรอตรวจสลิป รอรับงาน กำลังเติม และมีปัญหา พร้อมทางลัดเข้าคิว หน้าแรกเน้นงานที่ต้องทำ ส่วนตัวเลขสรุปอยู่ด้านบน (ข้อเสนอของผู้จัดทำ ยังเปลี่ยนได้)
2. ออเดอร์: ค้นหา กรองเกม/โซน/สถานะ/วันที่/ลูกค้า รายการอ่านง่าย ไม่ใช้ตารางกว้างบนมือถือ
3. รายละเอียดออเดอร์: Order ID แบบแสดงผล 10 ตัวอักษร, ลูกค้า, เกม, UID/Zone ID, โซนเกม, แพ็กเกจ, ราคาขาย, Supplier, ต้นทุน/เรท ณ ตอนซื้อ, สลิป, ผู้รับผิดชอบ และประวัติ ปุ่มตามสถานะติดด้านล่าง
4. แชท: รายชื่อลูกค้าและข้อความที่ยังไม่อ่าน หนึ่งบัญชีหนึ่งห้อง รายละเอียดลูกค้ามีทุกออเดอร์และแท็บเฉพาะรายการมีปัญหา ปุ่มติดต่อแอดมินไม่แนบเลขออเดอร์อัตโนมัติ
5. จัดการร้าน: เกมและแพ็กเกจ, ร้านต้นทาง, ราคาและกำไร, อัตราแลกเปลี่ยน และตั้งค่า
6. ตั้งค่า: บัญชีรับเงิน/คำแนะนำการโอน, การแจ้งเตือน, ประวัติกิจกรรม และสำรองข้อมูล เมนูทีมงานยังซ่อนในรุ่นแรก

ตัวอย่างโครงบนมือถือ:

```text
Squid first                         โปรไฟล์เจ้าของ
ยอดขายวันนี้        กำไรขั้นต้นวันนี้
รอตรวจสลิป | รอรับงาน | มีปัญหา
งานที่ต้องทำ
  ลูกค้า / เกม / แพ็กเกจ / สถานะ
  ลูกค้า / เกม / แพ็กเกจ / สถานะ
ภาพรวม        ออเดอร์        แชท        จัดการร้าน
```

บนจอกว้างให้แสดงรายการกับรายละเอียดเคียงกันได้ โดยใช้เส้นทางและข้อมูลชุดเดียวกับมือถือ รองรับธีม Telegram, safe areas, การเปิดคีย์บอร์ด และปุ่มย้อนกลับ ไม่กำหนดพาเลต/ฟอนต์สุดท้ายก่อนทบทวนหน้าตาจริง

## การเข้าถึงและสิทธิ์

- เปิดผ่านปุ่ม **จัดการร้าน** ของบอตปัจจุบัน ใช้ public HTTPS origin ที่กำหนดจริง ไม่ฝัง localhost ในเมนูบอต
- ตรวจ `Telegram.WebApp.initData` บนเซิร์ฟเวอร์ด้วยวิธี HMAC ตามเอกสาร Telegram และตรวจ Telegram user ID กับบัญชีแอดมิน ห้ามใช้ `initDataUnsafe` เป็นหลักฐานสิทธิ์
- ค่าที่เสนอ: อายุ initData ไม่เกิน 300 วินาที, เวลาอนาคตยอมได้ 30 วินาที, admin session อายุหนึ่งชั่วโมง ใช้ cookie HttpOnly/Secure/SameSite=Lax และ CSRF token สำหรับการเขียน
- ไม่ส่ง API_KEY หรือ bot token ไปที่เบราว์เซอร์ ไม่ใช้ API_KEY เป็นรหัสล็อกอิน Mini App
- ตารางแอดมินเตรียม `owner` และ `operator` แต่เปิดใช้เฉพาะ owner คนแรกจาก Telegram ID ที่ตั้งค่าอยู่ ไม่มี endpoint สมัครเป็นแอดมินเอง
- การออกจากระบบ/ปิดบัญชีต้องเพิกถอน session ได้ การอ่านสลิปและไฟล์สำรองตรวจสิทธิ์ทุกครั้ง

## ออเดอร์และการทำงานสองช่องทาง

- ใช้ state machine และบริการเดิมร่วมกัน ห้ามมีตรรกะเปลี่ยนสถานะอีกชุดเฉพาะหน้าเว็บ
- Backend ส่ง `allowed_actions` ให้ Mini App; บอตและเว็บต้องใช้แหล่งกติกาเดียวกัน
- คง paid → accepted → processing → completed และ completed → processing สำหรับแก้กดสำเร็จผิด ไม่ยกเลิกประวัติการรับเงินจริง
- เก็บ actor, channel, เวลา, ค่าก่อน/หลัง และ revision สำหรับการแก้ไข ใช้ idempotency key กับทุกคำสั่ง
- เมื่อข้อมูลเปลี่ยนจากอีกช่องทาง หน้าจอโหลดสถานะล่าสุด ไม่เขียนทับข้อมูลใหม่ด้วยฟอร์มเก่า
- เตรียมการรับผิดชอบงานแบบ atomic ไว้หนึ่งคนต่อออเดอร์ เพื่อรองรับแอดมินหลายคนในอนาคต
- สลิป PNG/JPEG/PDF อ่านผ่าน authenticated route; DTO ไม่ส่ง local file path ออกสู่หน้าจอ
- เปลี่ยนสถานะ/ตรวจสลิปไม่สร้างข้อความแชทฝั่งลูกค้า แชทจริงแยกจากประวัติกิจกรรมภายใน

## ร้านต้นทาง

- เริ่มจาก JorJee Game Store และ GGXG Store สวิตช์เดียวต่อร้าน: เปิดให้ดึงและใช้ราคา / ปิดทั้งสองอย่าง
- ปิดแล้วไม่นำร้านนั้นมาเลือกต้นทุนสำหรับราคา/ออเดอร์ใหม่ทันที ข้อมูลราคาเดิมและออเดอร์ที่สร้างแล้วคงอยู่
- ตรวจสวิตช์ก่อนเริ่มดึงและก่อน commit เพื่อกันงานที่กำลังรันเขียนข้อมูลหลังปิดร้าน
- เวลาดึงข้อมูลยังเป็น **15:00 <= เวลา < 16:00 Asia/Vientiane (UTC+7)** เท่านั้น อ่านข้อมูลและจัดการออเดอร์ได้ทั้งวัน
- แสดงเวลาดึงล่าสุด จำนวนแพ็กเกจ ผลรันล่าสุด ข้อผิดพลาด และสถานะข้อมูลเก่า
- ปิดทุกร้าน/ไม่มีข้อเสนอที่ใช้ได้: แพ็กเกจนั้นไม่พร้อมซื้อ ห้ามเลือกต้นทุนจากร้านที่ปิดหรือข้ามไปอีกโซน
- ร้านใหม่ต้องมีตัวเชื่อมข้อมูลและการตรวจสอบก่อนปรากฏเป็นตัวเลือกที่ใช้งานได้ ไม่รับ URL ใดก็ได้ไปดึงจากเซิร์ฟเวอร์

## เกม แพ็กเกจ และราคา

- เปิด/ปิดเกม โซน สินค้า และชุดแพ็กเกจที่เทียบกันได้ พร้อมตรวจรายการก่อนเผยแพร่
- โซนที่ไม่ทราบแน่ชัดแสดงว่ารอตรวจ ไม่สร้างคำว่า Global ขึ้นเอง
- เปรียบเทียบเฉพาะเกม/โซน/วิธีเติม/จำนวนและโบนัสที่เท่ากัน แพ็กเกจชื่อคล้ายกันไม่ถือว่าเท่ากันอัตโนมัติ
- เลือก Supplier อัตโนมัติราคาต่ำสุด หรือเลือกเองจากข้อเสนอที่ผ่านการตรวจและยังเปิดอยู่ ถ้าร้านที่เลือกเองใช้ไม่ได้ให้ขึ้นไม่พร้อมขาย ไม่แอบสลับร้าน
- กำหนดบวกจากทุนเริ่มต้น 10% (`1000` basis points) และปรับรายแพ็กเกจได้ แสดงตัวอย่างต้นทุน/ราคาขาย/กำไรขั้นต้นก่อนบันทึก
- ใช้เลขฐานสิบ/จำนวนเต็มและกติกาปัดเศษเดิม ห้ามใช้ floating point สร้างราคาชำระเงิน
- การแก้ชื่อ ราคา กำไร ร้านต้นทาง หรือเรท มีผลกับรายการใหม่ ออเดอร์เดิมใช้ snapshot เดิม

## อัตราแลกเปลี่ยน

- โหมด **LFX**: ดึงแถว USD เฉพาะช่วง 15:00–16:00 เก็บลงฐานข้อมูลแล้วเว็บใช้ค่าที่เก็บไว้ ไม่เรียก LFX ทุกครั้งที่เปิดหน้า
- โหมด **กำหนดเอง**: เจ้าของกรอก `1 USD = ... LAK`; เลือกโหมดนี้แล้วข้อมูล LFX ที่เก็บใหม่ไม่เปลี่ยนเรทที่ใช้ขาย จนกว่าจะสลับกลับ
- แสดงเรทที่ใช้งาน แหล่งที่มา โหมด เวลาดึง/บันทึก และประวัติ พร้อม preview ราคาก่อนบันทึก
- เรท `22,675.43 LAK` และ `-0.52%` ที่แจ้งในบทสนทนาเป็นตัวอย่างจากผู้ใช้ ไม่ถือเป็นการตรวจสอบ LFX สดหรือคำสั่งอัปเดตฐานข้อมูล
- หาก source ไม่บอกวันเผยแพร่ ให้เก็บ/แสดงว่าไม่ทราบ ไม่เอาวันดึงไปอ้างว่าเป็นวันประกาศ ค่าเปอร์เซ็นต์แสดงเฉพาะเมื่อพิสูจน์ field จาก source ได้
- ดึงไม่สำเร็จให้คงค่าล่าสุดพร้อมเตือนข้อมูลเก่า หากไม่มีค่าที่ใช้ได้เลยให้ระงับ quote USD ไม่สร้างราคาเป็นศูนย์

## ตัวเลขสรุปและข้อมูลปฏิบัติการ

- แยกยอดออเดอร์/ชำระเงิน/เติมสำเร็จ/คืนเงิน ไม่นับ pending เป็นรายได้สำเร็จ
- กำไรที่มีข้อมูลครบคำนวณจากราคาขายและต้นทุน/เรทที่บันทึกตอนสร้างออเดอร์ ระบุเป็นกำไรขั้นต้นก่อนค่าใช้จ่ายที่ยังไม่ได้เก็บ
- MOCK ไม่รวมในยอดจริง มีตัวกรองดูข้อมูลทดสอบได้
- เก็บข้อมูลออเดอร์ที่ย้อนสถานะและคืนเงินโดยไม่คิดรายได้ซ้ำ ช่วงวันรายงานใช้ Asia/Bangkok
- สำรองฐานข้อมูลพร้อมไฟล์สลิปและ manifest; ทดสอบกู้คืนในฐานข้อมูลแยก ไม่ทดลอง restore ทับระบบจริง

## ขอบเขตยังไม่ทำในรุ่นแรก

- ไม่ซื้อ/เติมผ่าน Supplier อัตโนมัติ ไม่โอน/คืนเงินจริงอัตโนมัติ
- ไม่เพิ่มการชำระเงินออนไลน์แทนการตรวจสลิปด้วยมือ
- ไม่เปิดจัดการทีมหลายคนบน UI แต่โครงข้อมูลและ permission checks ต้องเตรียมไว้
- ไม่เปิด checkout ลูกค้าจริงหรือเพิ่มเกมใหม่ที่ยังไม่ผ่านการตรวจเพียงเพราะ Admin Mini App พร้อม
- ไม่แก้ token, เปลี่ยนบอต, เปิดสู่สาธารณะ หรือ deploy จากการเขียนเอกสารแผนนี้

## เกณฑ์พร้อมใช้งาน

เข้า Mini App ด้วยบัญชีเจ้าของได้ คนอื่นเข้าไม่ได้; ออเดอร์/แชททำงานสองช่องทาง; สวิตช์ร้านและโหมดเรทมีผลจริงโดยไม่เปลี่ยนออเดอร์เดิม; หน้ามือถือใช้งานได้; ไม่มี secret หรือเส้นทางไฟล์รั่ว; กู้คืนข้อมูลทดสอบได้; ผ่านชุดทดสอบเดิมและชุดใหม่ก่อนตั้งปุ่มเปิด Mini App ไปยัง HTTPS URL จริง
