# แผนปรับ UI เดิมของ Squid first ให้ตรง Google Stitch

> สำหรับผู้ลงมือ ให้ใช้ Superpowers `executing-plans` และปิดงานทีละชุดเมื่อมีหลักฐานตามเกณฑ์ด้านล่าง

**เป้าหมาย** ปรับหน้าจอแอดมินที่ใช้งานอยู่ให้ตรงกับแบบและเส้นทางที่อนุมัติ ทั้ง Telegram Mini App และเว็บเดสก์ท็อป

**แนวทาง** ตรวจของเดิมเทียบกับแบบรายเส้นทาง แล้วแก้เฉพาะส่วนที่ต่าง ใช้คอมโพเนนต์และ API เดิมสำหรับข้อมูลจริง ใช้ฐานข้อมูลพรีวิวสำหรับสถานการณ์ทดสอบ

**ลำดับแพลตฟอร์ม** ปิดงานบนมือถือและ Telegram Mini App ก่อน แล้วจึงกลับมาตรวจเดสก์ท็อป

**ระบบ** React + Vite, Fastify, PostgreSQL/PGlite และ Playwright

**อ้างอิง** [กฎโปรเจกต์](../../../AGENTS.md) · [Google Stitch](https://stitch.google.com/projects/9946906478898127464) · [Design System](../../../.stitch/DESIGN.md) · [ตารางหน้าจอและเส้นทาง](../../design/screen-route-matrix.md) · [ขอบเขตรุ่นแอดมิน](../specs/2026-11-23-stitch-implementation-scope.md)

## กติกาทุกชุดงาน

- ก่อนแก้ เปิด Stitch แล้วบันทึกรหัสหน้าจอ แพลตฟอร์ม และสถานะที่ใช้เทียบ ระบุหน้าต้นทาง วิธีเข้าหน้านั้น การกระทำหลัก และทางกลับ
- เมื่อแบบมีหลายเวอร์ชัน ให้ใช้ตัวที่อนุมัติสำหรับเส้นทางและแพลตฟอร์มนั้น คงข้อกำหนดล่าสุดเรื่องกริดไอคอนเกมอย่างเดียว แพ็กเกจแยกตามเกม และปล่อยรายการว่างเมื่อไม่มีข้อมูล
- ตรวจตัวอักษรไทย สี ระยะห่าง ตำแหน่งปุ่ม ไอคอน และลำดับส่วน ใช้ UI โทนสว่างและสีหลัก `#2563EB` ตาม Design System ปัจจุบัน
- รักษาการยืนยันสิทธิ์ การเลือกสถานะออเดอร์ตามจริง เรทและต้นทุนใน snapshot เดิม รวมถึงเงื่อนไขรอบดึงข้อมูล `15:00–16:00 UTC+7`
- วัดความคืบหน้าจากจำนวน **คู่เส้นทางและสถานะที่ผ่านทั้งการเทียบภาพและการลองใช้งาน** ส่วนที่รอแบบหรือรอข้อมูลให้นับเป็นงานค้าง ภาพพรีวิวเดิมช่วยตั้งต้นการตรวจรอบใหม่

### 4. แชทและประวัติลูกค้า

ช่องค้นหารายการแชทตามเฟรม `3b3e068526f1415fb2847a6eff97e99d` รองรับชื่อลูกค้า, UID และเลขออเดอร์ทั้งแบบเต็มและแบบที่แสดงหน้าจอ ทดสอบ `#SQ-98417` แล้วพบลูกค้าคนเดียวและเปิดห้องที่ตรงกัน ภาพพรีวิว 390 px อยู่ที่ `artifacts/stitch-mobile-final/chat-order-search-390.png`

เมื่อค้นด้วยเลขออเดอร์ การ์ดแสดงออเดอร์ที่พบและเปิดรายละเอียดจากการ์ดได้โดยตรง แม้ลูกค้าจะมีออเดอร์ใหม่กว่า ทดสอบเปิด `#SQ-98417` จากรายการแชทและย้อนกลับแล้วคำค้นยังอยู่ ภาพล่าสุดที่ `artifacts/stitch-mobile-final/chat-matched-order-390.png`

เก็บรหัสคำขอส่งข้อความไว้กับร่างของแต่ละห้องจนได้รับผลยืนยัน การทดสอบใช้ API ของพรีวิวเพื่อบันทึกข้อความแล้วจำลองให้ผลตอบกลับสูญหาย จากนั้นออกจากห้องและกลับมาส่งร่างอีกครั้ง พบเพียงรายการเดียวในประวัติห้อง

จัดวางสลิปล่าสุดระหว่างข้อความตามเวลาอัปโหลดและแสดงเวลาในรายการแชท สลิปยังใช้เลขออเดอร์และข้อมูลจริงจาก API หลักฐานจอ 390 px อยู่ที่ `artifacts/stitch-mobile-final/chat-receipt-timeline-390.png`

รอบถัดมาใช้ HTML export ของ Conversation `437e4d2539c544c08294739d89c7d6b8`, Customer Profile `cfdddd9508d14eefabde4eb855a78b86` และ Support Desk `7146759022044c28a28d7c83a86ad61e` ตรวจจาก `artifacts/stitch-customer-acceptance/` โปรไฟล์ค้นชื่อ ไอดีบัญชี หรือ UID จากข้อมูลจริง และแสดงยอดออเดอร์สำเร็จกับบันทึกภายในล่าสุด API เดิมยังรองรับผู้เรียกเดิมและเพิ่มข้อมูลอ่านอย่างเดียว
