# Catalog API Implementation Plan

Goal: a runnable catalog API with persistent storage and a separate live scraper.

Architecture: validated complete snapshots flow from Playwright into an atomic database transaction; Fastify serves stored packages.

Tech stack: Node.js, TypeScript, Playwright, Fastify, pg, PGlite (local mode).

Spec: ../specs/2026-11-18-catalog-design.md

## Constraints and review focus
- Preserve prior data on invalid or incomplete scrape.
- Repeated syncs must not duplicate packages; missing items become inactive.
- Seed must retain original observation date and cannot replace live data.
- API must reject unknown games and optionally enforce a key.
- Worker must not overlap refreshes; external database locks serialize writers.
